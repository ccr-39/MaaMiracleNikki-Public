# MMN - 奇迹暖暖小助手：GUI 使用说明

MaaMiracleNikki（MMN）· [项目说明](../README.md) · [新手教程](../docs/USER_GUIDE.md)

基于 MaaFramework 的《奇迹暖暖》日常自动化工具。本文先介绍普通用户的连接配置，再保留任务设置与实现细节。Windows 用户使用完整解压的运行包，无需安装 Python；下载状态与安装方法见[项目说明](../README.md#下载与安装)。

## MuMu 15 从零配置

ADB 可以理解为 MMN 与模拟器之间的通信工具。你不需要先学习 ADB 命令，只需找到**目标实例的地址、模拟器自带的 ADB 文件**；自动启动是之后可以选择开启的额外功能。

本文以 MuMu 15（Android 15 实例）为例。**`<实例ADB端口>`、`<MuMu安装目录>` 和 `<Android版本>` 是占位符，须替换成自己电脑的实际值，不要输入尖括号；端口须为 1–65535 的数字。实例编号也须按实际情况填写。** MuMu 的软件版本、安装位置及多开实例不同，入口和路径也可能不同。

### 连接地址：找到正在使用的实例端口

“连接地址”是**模拟器的 ADB 连接地址**，不是游戏服务器地址、账号，也不是任意 IP。模拟器与 MMN 在同一台电脑时，`127.0.0.1` 表示“这台电脑”，冒号后的端口用于区分实例。

1. 打开 MuMu 主窗口（多开器），找到安装了《奇迹暖暖》的实例，记下它的**名称和编号**，点击该行的启动按钮，等待 Android 桌面出现。
2. 在 MuMu 的设置中确认 ADB 调试已开启；如果修改后提示重启，先正常重启该实例。ADB 调试选项位置随版本变化，以当前 MuMu 设置为准。
3. 在**主窗口（多开器）右上角菜单 → 设置中心 → 页面底部“ADB 端口”**查看正在运行的多开端口。注意这里指 MuMu 主窗口，不是游戏内设置。入口参考 [MAA 连接文档中的 MuMu 说明](https://docs.maa.plus/zh-cn/manual/connection.html#模拟器端口相关文档)；若版本界面不同，请在 MuMu 的设置或帮助中查找“ADB 端口”，不要套用其他实例或旧版本的固定端口。
4. 按实例名称、编号找到目标实例的那一项。记下显示的数字端口，用它替换 `127.0.0.1:<实例ADB端口>` 中的占位符；如果已显示完整地址，按显示值填写。**`<实例ADB端口>` 只是占位符，每台电脑、每个实例可能不同；实例编号不是端口号。**
5. 多开时将“实例名称 / 编号 / ADB 端口”对应记录。无法判断对应关系时，先正常关闭其他实例，仅保留目标实例，再查看运行中的端口；最后通过 MMN 截图预览确认画面和账号。不要以“哪个窗口在最前面”判断连接对象。

回到 MMN，进入“设置 → 连接设置”，在“连接地址”填写刚找到的完整地址，例如 `127.0.0.1:<实例ADB端口>`。不要只填 `127.0.0.1`、只填端口或带有中文冒号的地址。

### ADB 路径：选择模拟器自带的文件

“ADB 路径”要选择 MuMu 安装目录中实际存在的 **`adb.exe` 文件**。它不是模拟器启动程序，也不是一个文件夹。

1. 在 Windows 桌面或开始菜单找到 MuMu 快捷方式，右键打开“属性”，查看“目标”，或点击“打开文件所在的位置”。如果先打开的是快捷方式所在文件夹，再对其中的 MuMu 快捷方式查看属性，找到实际 EXE 的位置。
2. 找到 MuMu 的实际安装目录后，查找 `nx_device` 文件夹；MuMu 15 的一个示例位置是：

   ```text
   <MuMu安装目录>\nx_device\<Android版本>\shell\adb.exe
   ```

   将 `<MuMu安装目录>` 替换为快捷方式所指向的实际安装目录，`<Android版本>` 替换为实际子目录名。不要新建占位目录或填写不存在的路径。
3. 在 MMN“设置 → 连接设置”的“ADB 路径”右侧点击 **“选择…”**，进入自己的目录，选中 `adb.exe` 后点击文件对话框的“打开”。确认文本框显示的是这个文件的完整路径。Windows 隐藏扩展名时，它可能显示为 `adb`，文件类型应为应用程序。
4. 示例路径不存在时，在**实际 MuMu 安装目录**的文件资源管理器搜索框中搜索 `adb.exe`，优先选择目标 Android 15 安装目录下的文件。也可在 MuMu 运行时打开任务管理器，右键对应进程 →“打开文件所在的位置”，再定位安装目录；不要选择无关软件的 ADB 或只选 `MuMuNxMain.exe`。

新手建议明确选择文件。ADB 路径留空虽有自动查找规则，但并不保证找到你当前使用的 MuMu；明确填写的路径不存在会报错，不会偷偷换用其他 ADB。无需额外下载来历不明的 ADB 或 DLL。

### 可选：自动启动模拟器

**默认关闭。** 如果你每次自己打开 MuMu，可以不勾选“设备未就绪时自动启动模拟器”，也不必填写“启动程序”和“启动参数”（若另行开启完成后关闭模拟器，仍需配置启动程序）。建议先按下一节手动完成一次连接测试，再设置自动启动。

1. 按上节的快捷方式属性或“打开文件所在的位置”找到 MuMu 安装目录，在 `nx_main` 文件夹查找 `MuMuNxMain.exe`。示例：

   ```text
   <MuMu安装目录>\nx_main\MuMuNxMain.exe
   ```

2. 进入 MMN“设置 → 定时与启动”，勾选 **“设备未就绪时自动启动模拟器”**。
3. 点击“启动程序”右侧的 **“选择…”**，选择自己电脑上的 `MuMuNxMain.exe`；不是选择上一节的 `adb.exe`，也不是 `.lnk` 快捷方式。选不到时在真实安装目录搜索 `MuMuNxMain.exe`，不要照填示例路径。
4. **MuMu 首次建议“启动参数”留空。** 此时 MMN 会按下面的条件查找实例，不需要手动猜编号。

参数留空时，必须同时满足：

- 所选程序文件名为 `MuMuNxMain.exe` 或 `mumu-cli.exe`；程序所在目录中存在 `mumu-cli.exe`。
- “连接地址”是本机端口地址：`127.0.0.1:数字端口`、`localhost:数字端口` 或 `[::1]:数字端口`。`emulator-5554` 这类序列号不能用于此自动匹配。
- 启动程序上一层目录中的 `vms/MuMuPlayer-*/configs/vm_config.json` 可读，实例目录名符合 `MuMuPlayer-12-编号`、`MuMuPlayer-15-编号` 或带小版本号的对应格式；其中 `vm.nat.port_forward.adb.host_port` **恰好有一个**与填写的端口匹配。该配置由 MuMu 管理，普通用户无需手动修改。

匹配成功后，MMN 使用同目录的 `mumu-cli.exe`，传入匹配出的实例编号和 Android 版本启动；**不会按窗口顺序、默认实例或固定端口猜测**。没有匹配、多条匹配、缺少 CLI 或配置不可读时，会提示“未能按 ADB 地址唯一匹配 MuMu 实例”并停止本次执行，不会自动打开另一个实例。

匹配失败时，先手动打开目标实例，重新查看实际端口，核对连接地址和启动程序是否属于同一套 MuMu 安装目录；不要修改实例配置来强行匹配。仍失败可关闭自动启动，改为每次手动打开模拟器。熟悉 MuMu 命令行的用户也可选择实际 `mumu-cli.exe`，在“启动参数”中填写 `control --vmindex 实际编号 --version 15 launch`（仅适用于对应 Android 15 实例；必须替换“实际编号”，并核对本机 MuMu CLI 支持的命令）。**非空参数会跳过自动实例匹配**，由所选程序按你填写的参数执行；不要把 CLI 参数直接套到其他启动程序，也不要用端口号代替实例编号。等待连接的目标仍是“连接设置”里填写的地址。

该功能用于手动开始任务和每日定时开始任务；指定设备已就绪时不会重复启动。启动后最多等待 120 秒确认指定实例的 Android 已启动，期间可点击“停止”。它不负责电脑开机、唤醒或自动处理游戏登录、验证码；离线演练不启动模拟器。

**两个开关的区别：**

| 选项 | 用途 | 何时生效 |
| --- | --- | --- |
| 设置 → 连接设置 → 自动连接指定地址 | 对填写的 TCP 地址建立 ADB 连接，不打开模拟器窗口。 | “连接与截图测试”及任务连接；关闭时这些步骤只使用已连接设备。 |
| 设置 → 定时与启动 → 设备未就绪时自动启动模拟器 | 在指定设备未就绪时执行模拟器启动程序。 | 手动或定时开始任务；“检测设备”和“连接与截图测试”不会触发启动。 |

两项均默认关闭，开启其中一项不会替你勾选另一项。自动启动流程自身检查、等待本机设备就绪时，也会尝试连接所填 TCP 地址；这不等于已经开启“自动连接指定地址”。新手使用本机 MuMu 时，可明确勾选后者以便连接测试，是否需要自动启动另行决定。

### 完整操作示例

先记下目标实例的实际 ADB 端口，用它替换下文的 `<实例ADB端口>`，再找到自己电脑上两个 EXE 的真实位置：

1. **启动模拟器**：从 MuMu 多开器打开目标实例，等待桌面出现，确认 ADB 调试开启。建议竖屏 `900 × 1600`，安装《奇迹暖暖》国服客户端。
2. **查找端口**：按实例名称、编号在多开器设置中核对 ADB 端口，记为下文的 `<实例ADB端口>`。
3. **填写连接地址**：MMN“设置 → 连接设置 → 连接地址”填 `127.0.0.1:<实例ADB端口>`。
4. **选择 ADB 路径**：点“ADB 路径”旁“选择…”，选中实际的 `adb.exe`。
5. **检测设备**：点击“检测设备”，查看“已发现设备”。检测只列出当前 ADB 已知的设备，**不会扫描端口或主动连接**。首次列表为空不一定是失败：保持手填地址，勾选“自动连接指定地址”，先点击“连接与截图测试”；成功后再点击“检测设备”。
6. **选择设备**：在“已发现设备”下拉列表中选中 `127.0.0.1:<实例ADB端口>` 对应的在线设备，核对“连接地址”未变成其他实例。只有一个在线设备且地址为空时可自动填入；多个实例应自行选择。离线和未授权项不能作为在线目标选择。
7. **连接与截图测试**：保持勾选“自动连接指定地址”，点击“连接与截图测试”。成功后应看到型号、Android 版本、截图尺寸和预览。核对画面确实来自目标实例；必要时先在目标窗口打开游戏，手动确认账号，再重新测试。检测和截图测试不执行游戏任务，也不会启动、重启或关闭模拟器。
8. **勾选任务**：手动完成游戏登录、授权及验证码，回到“每日任务”；第一次先勾选“启动”，再按需选择其他任务，点击齿轮核对消费相关子选项。新配置的 14 个任务默认全部不勾选。
9. **开始**：确认设置底部显示“已自动保存”，点击“开始任务”。运行时不要切换实例或手动操作游戏；需要中止时点击“停止”，等待安全结束。

### 连接常见问题

| 现象 | 先这样处理 |
| --- | --- |
| `10061`、积极拒绝连接 / connection refused | 通常表示填写的端口当前没有接受连接。启动正确实例并等待 Android 桌面出现，确认 ADB 调试开启；重新查看该实例的端口，核对地址后再测试。仅打开多开器、不启动实例通常不够；不要照抄示例端口。 |
| “检测设备”列表为空 | 先检查 ADB 路径有效，再手填真实地址，勾选“自动连接指定地址”并点“连接与截图测试”；成功后重新检测。检测不会主动连接，也不会查找任意端口。 |
| `offline`（离线） | 等待实例完全启动后重新测试；仍离线时先停止 MMN 任务，正常重启目标实例，重新查看端口，使用同一套 MuMu 的 ADB 再连接。若同时运行其他使用 ADB 的助手，先退出这些助手后再试。不要选择离线项运行任务。 |
| `unauthorized`（未授权） | 查看模拟器是否弹出“允许 ADB / USB 调试”提示，确认来源后允许，再重新测试；没有弹窗时检查 MuMu 的调试设置，必要时正常重启目标实例。 |
| 提示 ADB 文件不存在 | 通过 MuMu 快捷方式属性找真实安装目录，在其中搜索 `adb.exe`，重新点击“选择…”选文件；软件迁移或升级后原路径可能改变。不要只选目录或启动程序。 |
| 预览是别的账号 / 实例 | 停止任务，回多开器核对实例名称、编号和端口，重新填写地址、选择在线设备并截图确认；前台窗口不是选取依据。 |
| 自动启动提示无法唯一匹配 | 核对本机地址、实际端口、启动程序与 `vms` 是否来自同一套安装，且有同目录 `mumu-cli.exe`。仍失败先关闭自动启动、手动打开实例；需要显式参数时按上节选择正确程序并填写真实实例参数。 |
| 检测或测试按钮不可用 | 确认没有正在执行任务、没有尚未结束的检测，并关闭“设置 → 运行设置 → 离线演练（不连接设备）”；离线演练默认关闭，开启后不允许设备测试。 |

## 界面与任务设置细节

界面使用统一浅色主题：浅灰背景、白色圆角卡片、蓝色选中态，以及自带矢量勾选和下拉图标；每日任务和设置页共享控件样式。主题集中在 `gui/theme.py`。
“设置 → 软件更新”支持启动后后台检查官方 GitHub 稳定版、查看说明、确认下载和安装。可关闭自动检查；安装可等待任务完成或先安全停止。开发模式仅检查/下载。当前提供 v0.1.2-rc.2 公开 Pre-release，没有稳定版；请从仓库 README 中的 Release 入口手动下载，内置更新不会提供测试版。详见 [更新协议与回滚](../docs/SOFTWARE_UPDATES.md)。
所有下拉菜单在原控件下方展开，屏幕下方空间不足时改在上方展开，保持原值可见。连接方式统一为通用 ADB，支持 MuMu、雷电、蓝叠、夜神等；原 MuMu 配置自动兼容为通用 ADB，不再显示重复选项。

## 选择任务与子选项

每日任务页包含任务列表、任务参数、运行状态与日志三栏。勾选启用任务，点击任务旁的齿轮设置子选项；只切换选中项不会改变勾选。首次 14 个任务组全部不勾选，任务按固定顺序执行。

| 任务 | 用户需要核对的选项 |
| --- | --- |
| 启动 | 游戏登录、授权和验证码由用户手动处理。 |
| 签到 | 可选补签及免费/50钻/100钻档位、限时活动签到；补签可能消耗钻石，活动签到只领取免费奖励。 |
| 搭配师联盟 | 可选整理资料 3 次，其中第 2、3 次消耗金币。 |
| 搭配竞技场 | 免费挑战及奖励领取。 |
| 搭配评选赛 | 投票 1–30 次，默认 20；可选“我要参赛”。 |
| 织梦人学会 | 委托及免费探索；缺衣时可能用金币补购。 |
| 小屋 | 生活点滴和随机拜访 5 次。 |
| 好友 | 一键送心。 |

补签、限时签到、好友邮件、额外整理、参赛及金币抽取默认关闭。费用保护不能代替用户核对，首次请少量选择并观察。任务详情见[完整功能说明](../README.md#功能)；限时签到见[专项说明](../docs/limited-signin.md)。

## 开始、停止与恢复

设置输入后约 400 毫秒自动保存；开始和关闭窗口前也会保存。无效地址或参数会阻止开始，保存失败时点击“重试保存”。运行期间任务勾选和参数锁定，可以切换任务查看说明。

点击“开始任务”运行当前选择；默认失败即停止。开启“任务失败后继续下一项”后，仍须成功恢复主页才会继续。点击“停止”后等待当前操作安全结束，不能保证立即中断；运行中关闭窗口也会先等待停止。

状态区显示等待、执行中、完成、跳过、失败、已停止或未执行。失败后可“重试失败项”或“继续未完成”，操作前核对游戏页面、消费和奖励结果。修改地址或执行模式后应开始新一批，避免混用不同设备结果。

设置中的“离线演练”只演示队列，不连接 ADB、不打开或关闭模拟器；演练完成不表示游戏任务完成。首次正常使用应关闭该选项，再手动完成连接与截图测试。

## 定时与模拟器启停

在“设置 → 定时与启动”开启每日定时并填写一个 `HH:mm` 时刻。电脑须开机且 MMN 保持运行（可最小化）；到点执行已勾选任务并补上启动游戏。忙碌、休眠或错过时间时跳过，不补跑、不唤醒电脑，也不提供 Windows 开机自启。同一分钟内重启 MMN 可能再次触发，应避免此时重启。

“设备未就绪时自动启动模拟器”默认关闭，手动开始也适用。使用前选择 MuMu 启动程序、核对实例地址与参数，具体规则见[自动启动配置](#可选自动启动模拟器)。无法唯一匹配时不会猜选默认实例。

“设置 → 运行设置 → 全部任务完成后关闭模拟器”单独开启；还需填写 MuMu 启动程序。只有非空真实队列全部成功且未请求停止时才正常关闭指定实例；失败、停止、演练或匹配失败时不会关闭。请求成功不保证窗口已退出，请观察实际结果。

## 日志、配置与更新

界面日志支持自动滚动、复制、展开和清空；清空界面不删除详细日志。失败反馈前先检查并脱敏日志，不要上传账号画面或整个 `userdata`。系统桌面通知能否显示取决于 Windows 通知设置。

配置保存在 EXE 同目录 `userdata/config/gui.json`，无需手动复制模板。更新前退出程序并备份 `userdata`，完整替换运行文件，不要混用不同版本的 `_internal`。配置迁移见[迁移说明](../docs/CONFIGURATION_MIGRATION.md)。
